## Figures and steps

Diagrams are numbered automatically. <FigRef id="idempotent-retry" /> shows how a retried request is deduplicated.

<Steps>
1. The client sends `POST /v1/notifications` with an `Idempotency-Key` header.
2. The API stores the key only if it does not already exist.
3. The store reports that the key was created.
4. The API accepts the request with `202 Accepted`.
</Steps>

A key phrase the reader must not miss: <Highlight>we integrate with providers</Highlight>.

## Estimates and trade-offs [#estimates-and-tradeoffs]

**Assumption:** 10M daily active users, 5 notifications per user per day, peak factor ×5.

<Estimate title="Traffic">
| Quantity       | Formula              | Result         |
| -------------- | -------------------- | -------------- |
| Daily sends    | 10M DAU × 5 / user   | 50M / day      |
| Average rate   | 50M ÷ 86,400 s       | ≈ 580 msg/s    |
| Peak rate (×5) | 580 × 5              | ≈ 2.9k msg/s   |
</Estimate>

<Tradeoffs>
| Decision           | Chosen                 | Alternative   | Why                                              |
| ------------------ | ---------------------- | ------------- | ------------------------------------------------ |
| Delivery semantics | At-least-once + dedup  | Exactly-once  | Cheaper; an idempotency key makes retries safe   |
| Dedup store        | Key-value with TTL     | Relational    | Single-key lookups; keys expire after 24 h       |
</Tradeoffs>

## Code

```ts title="dedup.ts" {3-5}
export async function accept(key: string, send: () => Promise<void>) {
  // SET NX with a TTL: only the first request with this key proceeds.
  const created = await store.set(key, "1", { nx: true, ttlSeconds: 86_400 });
  if (!created) return { status: 202, deduplicated: true };
  await send();
  return { status: 202, deduplicated: false };
}
```
